# راهنمای مدل مالی آتیوار

این پوشه یک مدل مالی ماه‌به‌ماه دارد که سه سناریو (پایه / استرس / شدید) را برای ۳۶ ماه شبیه‌سازی می‌کند. فقط پایتون استاندارد لازم است؛ هیچ کتابخانه‌ای نصب نمی‌شود.

---

## ۱. اجرای سریع

**ویندوز (دابل‌کلیک یا CMD):**

```bat
founder\run-model.bat
```

**یا دستی:**

```powershell
python founder\financial_model.py
python founder\test_financial_model.py -v
```

اگر همهچیز درست باشد، آخرین خط `OK — model rebuilt and all tests passed.` است.

---

## ۲. چه فایلی ساخته می‌شود

| فایل | محتوا |
| --- | --- |
| `founder/financial-model.md` | گزارش خوانا: فرض‌ها، مقایسه سه سناریو، جدول ماه‌به‌ماه پایه، خلاصه فصلی استرس و شدید، پنج یافته |
| `founder/financial-model.csv` | ۱۰۸ ردیف خام (۳ سناریو × ۳۶ ماه) با همه ستون‌ها، برای اکسل |
| `founder/financial_model.py` | خود مدل؛ فرض‌ها بالای فایل در `SCENARIOS` |
| `founder/test_financial_model.py` | ۹ تست خودکار |

هر بار اجرا، هر دو فایل از نو ساخته می‌شوند. چیزی دستی ویرایش نکن؛ منبع، اسکریپت است.

## ۳. سه راه چک کردن

### راه اول: تست خودکار (سریع‌ترین)

```powershell
python founder\test_financial_model.py -v
```

باید ۹ تست `ok` بدهند:

| تست | چه چیزی را ثابت می‌کند |
| --- | --- |
| `test_base_headline` | ماه ۹ = ۶۱۶٬۷۹۸ حساب؛ بازگشت ماه ۲۱ |
| `test_stress_headline` | ماه ۹ = ۲۱۹٬۹۳۳ حساب؛ EBITDA ماه ۱۲ ≈ ۰٬۱ |
| `test_severe_cash_gap` | نقد در ماه ۶ تمام می‌شود |
| `test_active_recurrence` | فرمول حساب فعال: `فعال = فعال قبلی × (۱ − ریزش) + جذب` |
| `test_revenue_and_cash_identities` | درآمد = فعال × ARPU × سهم مجوز؛ نقد = نقد عملیاتی + ترانش |
| `test_marketing_budget_and_reach_cap` | خرج بازاریابی از بودجه و سقف کانال بیشتر نمی‌شود |
| `test_marketing_budget_18_months` | بودجه ۱۸ ماه: ۱۰ / ۹ / ۳ میلیارد |
| `test_report_contains_headline` | گزارش، عدد ۶۱۶٬۷۹۸ و ماه ۲۱ را دارد |
| `test_csv_output_has_108_rows` | CSV دقیقاً ۱۰۸ ردیف داده دارد |

### راه دوم: چک دستی یک ردیف (مهم‌ترین)

ماه اول سناریوی پایه را خودت حساب کن:

| مرحله | محاسبه | نتیجه |
| --- | --- | ---: |
| جذب | ۰٬۴ میلیارد بودجه ÷ ۱۰٬۰۰۰ تومان CAC | ۴۰٬۰۰۰ حساب |
| درآمد | ۴۰٬۰۰۰ × ۱۴٬۰۰۰ | ۵۶۰٬۰۰۰٬۰۰۰ تومان (۰٬۵۶ میلیارد) |
| هزینه متغیر | ۰٬۵۶ × ۱۵٪ | ۸۴٬۰۰۰٬۰۰۰ |
| هزینه ثابت | — | ۲٬۵۸۰٬۰۰۰٬۰۰۰ |
| بازاریابی | — | ۴۰۰٬۰۰۰٬۰۰۰ |
| EBITDA | ۰٬۵۶ − ۰٬۰۸۴ − ۲٬۵۸ − ۰٬۴ | **−۲٬۵۰۴٬۰۰۰٬۰۰۰** |
| نقد | ۱۵ میلیارد ترانش − ۲٬۵۰۴ | **۱۲٬۴۹۶٬۰۰۰٬۰۰۰** |

در جدول گزارش، همین ردیف به‌خاطر گرد کردن یک‌رقمی این‌طور دیده می‌شود: درآمد `0.6`، EBITDA `-2.5`، نقد `12.5`. اگر با CSV چک کنی، عدد کامل را می‌بینی.

### راه سوم: چک یک ماه خاص در CSV

فایل `founder/financial-model.csv` را در اکسل باز کن و ردیف `scenario=base, month=9` را ببین:

- `active` باید ۶۱۶٬۷۹۸ باشد.
- `revenue` باید ≈۸٬۶۳۵٬۱۷۳٬۵۵۶ تومان باشد (۸٬۶ میلیارد).
- `cash` باید ۵۱٬۵ میلیارد باشد (۵۰ ترانش + ۱٬۵ نقد عملیاتی).

اگر این سه بخوانند، مدل سالم است.

## ۴. چطور فرض‌ها را عوض کنم

فایل `founder/financial_model.py`، بالای فایل، دیکشنری `SCENARIOS`. هر سناریو این کلیدها را دارد:

| کلید | واحد | معنی |
| --- | --- | --- |
| `cac` | تومان | هزینه جذب هر حساب فعال |
| `churn` | اعشار | ریزش ماهانه (۰٬۰۵ = ۵٪) |
| `arpu` | تومان | درآمد ماهانه هر حساب |
| `variable_pct` | اعشار | سهم هزینه متغیر از درآمد |
| `marketing` | میلیارد تومان در ماه | بودجه بازاریابی هر ماه (لیست ۳۶ عددی یا یک عدد) |
| `fixed` | میلیارد تومان در ماه | هزینه ثابت هر ماه |
| `license_month` | ماه | از کدام ماه مجوز دارید |
| `pre_license_share` | اعشار | چه سهمی از درآمد قبل از مجوز قابل شناسایی است |
| `tranches` | دیکشنری ماه → میلیارد | ترانش‌های سرمایه |
| `reach_cap` | حساب | سقف نفوذ در کانال |

**مثال:** اگر می‌خواهی ببینی CAC ۱۲ هزار چه می‌کند، فقط `"cac": 10_000` را به `12_000` عوض کن و دوباره اجرا کن. تست‌ها ممکن است بشکنند (چون سرتیتر عوض شده)؛ این طبیعی است — تست‌ها برای همین‌اند که بفهمی چه چیزی جابه‌جا شد.

## ۵. چه چیزی مدل نشده

- مالیات، تورم، نرخ ارز، هزینه تأمین مالی
- درآمد آتی‌پوز به‌صورت جدا (در ARPU حل شده)
- فاز ۲ (طلا) و فاز ۳ (AI)
- ریزش غیرخطی یا فصلی
- رفتار رقبا

مدل برای **تست انسجام و ریسک** است، نه پیش‌بینی. هر عدد از یک فرض می‌آید و هر فرض قابل بررسی است.
